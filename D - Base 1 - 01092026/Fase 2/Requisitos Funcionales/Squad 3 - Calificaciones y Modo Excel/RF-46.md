## 2. Especificación funcional

### 2.1 Enunciado normativo
> **Cuando se registre una nota numérica entre 0 y 20 o un literal AD, A, B o C, el sistema deberá calcular en el servidor el par (valor vigesimal, literal CNEB) con los umbrales de la escala institucional vigente y almacenar ambos valores, rechazando cualquier entrada fuera de ese dominio.**

### 2.2 Descripción
El motor recibe el texto ingresado por el docente. Si es un número de 0 a 20, obtiene el literal comparando con los umbrales de la escala (AD, A, B; por debajo de B es C). Si es un literal, le asigna un valor vigesimal representativo. Ambos valores se guardan: el literal para libretas y SIAGIE, y el numérico para promedios y cuadros de mérito. El servidor no confía en conversiones hechas por el cliente.

### 2.3 Objetivo de negocio
Cumplir la calificación literal del CNEB sin perder la precisión numérica que la institución usa para promedios y méritos.

### 2.4 Actores
| Actor | Tipo | Participación |
| --- | --- | --- |
| Sistema (motor de conversión) | Principal | Valida y convierte |
| Docente / practicante | Secundario | Ingresa la nota |
| Squad 1 (RF-13) | Secundario | Define los umbrales de la escala |

### 2.5 Disparador
Llega al servidor una nota en un lote (RF-37), una rectificación (RF-43) o una carga Excel (RF-80).

### 2.6 Alcance
- **Incluye:** validación del dominio, conversión numérico→literal, literal→valor representativo, almacenamiento dual, insignia en la planilla.
- **Excluye:** definición de la escala (RF-13); promedios (RF-41); uso en cuadro de mérito (RF-61).

## 3. Contrato de ejecución

### 3.1 Precondiciones
- **PRE-01:** La planilla tiene una escala válida: 0 < B < A < AD ≤ 20.

### 3.2 Entradas
| ID | Dato | Tipo / formato | Obligatorio | Origen | Restricción |
| --- | --- | --- | --- | --- | --- |
| EN-01 | Nota ingresada | Texto | Sí | Docente | 0–20 con hasta dos decimales (punto o coma) o AD/A/B/C sin distinguir mayúsculas; máx. 30 caracteres |
| EN-02 | Umbrales de la escala | {ad, a, b} | Sí | Configuración institucional (RF-13) | 0 < b < a < ad ≤ 20 |

### 3.3 Salidas
| ID | Salida | Destinatario | Formato | Condición |
| --- | --- | --- | --- | --- |
| SAL-01 | Par {numeric, literal} almacenado en la celda | Planilla / consumidores | JSON | Éxito |
| SAL-02 | Insignia con literal y valor numérico entre paréntesis | Docente | Pantalla | Éxito |
| SAL-03 | Error `INVALID_GRADE` | Docente | JSON 400 | EX-01 |
| SAL-04 | Error `INVALID_SCALE` | Docente / soporte | JSON 422 | EX-02 |

### 3.4 Postcondiciones
- **POST-01 (éxito):** La celda almacena el valor numérico y el literal coherentes con la escala vigente.
- **POST-02 (fallo):** Si la entrada o la escala es inválida, no se almacena nada y el lote completo se rechaza (RF-37).

## 4. Comportamiento

### 4.1 Flujo principal
1. El servidor recibe la nota ingresada.
2. El sistema valida la escala (VAL-01).
3. El sistema identifica si la entrada es un literal o un número (VAL-02).
4. Para un número, el sistema asigna AD si es ≥ umbral AD, A si es ≥ umbral A, B si es ≥ umbral B y C en otro caso.
5. El sistema almacena el par numérico–literal (SAL-01) y la planilla muestra la insignia (SAL-02).

### 4.2 Flujos alternativos
- **FA-01 (paso 3):** La entrada es un literal; el sistema asigna su valor representativo (RN-NOT-26) y almacena el par.

### 4.3 Excepciones
- **EX-01 (paso 3):** Entrada vacía, no numérica, con más de dos decimales, en notación científica, infinita o fuera de 0–20 → SAL-03 → POST-02.
- **EX-02 (paso 2):** Umbrales de escala inválidos → SAL-04 → POST-02.

### 4.4 Reglas de negocio
- **RN-NOT-14:** Conversión oficial: 18–20 = AD, 14–17 = A, 11–13 = B, 0–10 = C. Fuente: RF-46 v1. En el sistema se aplica mediante los umbrales configurables de RF-13 (ver DP-01).
- **RN-NOT-26:** Valor representativo de un literal ingresado directamente: AD = 19, A = 15, B = 12, C = 8. Fuente: código `parseGrade` (ver DP-02).

### 4.5 Validaciones
| ID | Qué se valida | Cuándo | Si falla |
| --- | --- | --- | --- |
| VAL-01 | 0 < b < a < ad ≤ 20 y valores finitos | Paso 2 | EX-02 |
| VAL-02 | Formato `^\d{1,2}([.,]\d{1,2})?$` o literal AD/A/B/C | Paso 3 | EX-01 |
| VAL-03 | Valor numérico entre 0 y 20 | Paso 4 | EX-01 |

## 5. Verificación

### 5.1 Criterios de aceptación
```gherkin
Escenario: CA-01 Conversión de un número
  Dado una escala con umbrales AD 18, A 14 y B 11
  Cuando el docente registra "16"
  Entonces la celda almacena 16 y "A"
  Y la planilla muestra "A (16)"

Escenario: CA-02 Límites de la escala
  Dado una escala con umbrales AD 18, A 14 y B 11
  Cuando se registran "18", "17.99", "14", "11" y "10.99"
  Entonces los literales son "AD", "A", "A", "B" y "C"

Escenario: CA-03 Literal directo
  Dado la misma escala
  Cuando el docente registra "b"
  Entonces la celda almacena "B" con su valor representativo

Escenario: CA-04 Entradas inválidas
  Dado la misma escala
  Cuando se registra "21", "-1", "1e1", "15.555" o una celda vacía
  Entonces el sistema responde "INVALID_GRADE"
  Y no se almacena ninguna nota del lote

Escenario: CA-05 Escala mal configurada
  Dado una escala con umbral B mayor que el umbral A
  Cuando se registra cualquier nota
  Entonces el sistema responde "INVALID_SCALE"
  Y no se almacena ninguna nota
```
